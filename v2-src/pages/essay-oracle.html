Hosting a production site on Oracle's free tier — the complete $0 stack.

The page you're reading is served over TLS from an ARM instance that costs nothing, behind a CDN that costs nothing, with analytics that cost nothing. Here's the whole playbook — including the three ways it almost broke.

This is not a "works on my machine" post. The architecture below runs a live business site — contact form, analytics, monitoring, nightly backups — on Oracle Cloud's Always Free tier plus Cloudflare's free plan. Total monthly cost: zero. Total monthly invoices: zero. The catch is that free tiers punish carelessness, so most of this article is about the care.

The shape of it

One ARM VM (Ampere A1, 2 OCPU / 12 GB) runs nginx serving the static site, a small Node service for the contact form, and self-hosted Umami for analytics. Cloudflare sits in front as CDN, TLS terminator, and DDoS filter. Static assets are fingerprinted and cached for a year; HTML is always fresh. That last pair — immutable assets plus uncached HTML — is the whole trick behind both speed and safe deploys.

  • Compute: VM.Standard.A1.Flex — ARM, which matters (see below)
  • Edge: Cloudflare free — Universal SSL, caching, bot filtering, Turnstile
  • Web: nginx with brotli-static, HTTP/2, grade-A security headers
  • API: ~150 lines of Node behind nginx /api/, rate-limited
  • Analytics: Umami (self-hosted, cookieless, 1 KB script)
  • Backups: nightly tar + DB dump to Object Storage (10 GB free)

Why free-tier hosting needs more discipline than paid

Paid platforms absorb your mistakes: they autoscale, they buffer traffic, they restart things. The free tier does none of that. A viral share that would be a nothing-burger on Vercel can saturate a 10 Mbps link — unless your assets are cached at the edge, which is exactly what Cloudflare's free plan does. The discipline is the architecture: static-first (nothing computes unless it must), edge-cached (origin only serves HTML misses), and small (the whole site is under a megabyte).

There's also the reclamation policy. Oracle can idle-reclaim Always Free VMs that sit under a CPU threshold for a week. A site with real traffic plus an analytics service and a cron heartbeat never comes close to that line — but you should know the rule exists before you bet a client demo on it.

The three ways it almost broke

1. "Out of capacity" on instance creation. Popular regions run dry of free ARM capacity, sometimes for days. The fix is boring: a launch-retry loop (or picking a region with headroom) and the discipline to provision before you need it. Provision the VM the day you sign up, not the day of the launch.

2. ARM-only images. Every tutorial on the internet assumes x86. Some Docker images, panels, and PHP runtimes don't ship ARM64 variants. The nginx + Node stack in this playbook is aarch64-clean end to end — but verify each image tag before you write it into a runbook, not after.

3. The email deliverability trap. Free VMs can't send mail on port 25, and naive SMTP from a fresh IP lands in spam anyway. Oracle's free tier includes 3,000 sends/month through their Email Delivery service with proper SPF/DKIM/DMARC setup — use it, then test against Gmail, Outlook, and Yahoo before you trust it. A contact form that silently vanishes into a spam folder is worse than no contact form.

The nginx file that does most of the work

# the two lines that matter most
location /_assets/ {
    add_header Cache-Control "public, max-age=31536000, immutable";
}
location = / {
    add_header Cache-Control "no-cache";
    try_files /index.html =404;
}
# brotli pre-compressed at build time
brotli_static on;

Fingerprinted filenames plus immutable means every deploy is instantly live with zero cache-purge rituals, and no visitor ever sees new HTML with old CSS — the classic mid-deploy breakage. Add the security headers (HSTS, CSP, the usual suspects), origin-lock nginx to Cloudflare's IP ranges, and point SSH at a non-standard port with key-only auth.

What free-tier hosting is not

It's not a place for a database-heavy app expecting burst traffic, and it's not something I'd sell to a client as "managed." It's a superb deal for exactly this class of product — portfolios, marketing sites, MVPs, internal tools — where the architecture is static-first and the owner wants infrastructure to be a solved problem. When a project outgrows it, the entire site is one rsync away from any other host. Portability is the real premium.

The 15-minute version

  1. Provision the A1 VM (Ubuntu LTS), key-only SSH, security list locked to 80/443.
  2. Install nginx; drop in the site config with the caching and header blocks above.
  3. Move DNS to Cloudflare; proxy the record; issue an Origin CA cert for nginx.
  4. Deploy: rsync -az --delete dist/ vm:/var/www/ — that's the pipeline.
  5. Backups: nightly cron, tarball to Object Storage, a restore drill you actually watch succeed.

The full nginx config, the contact API, and the systemd units are in this site's repository — shipped as the deploy kit. Steal them; they're field-tested, which is worth more than they cost. Which was nothing.
